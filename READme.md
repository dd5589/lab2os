# Лабораторная работа №2. Безопасная обработка сетевых подключений и сигналов

## Описание
Реализован TCP-сервер, который обрабатывает сетевые подключения и сигнал `SIGHUP` в одном процессе.
Сервер ожидает новые подключения и данные от клиента. Одновременно он оставляет открытым только одно клиентское соединение: все дополнительные подключения закрываются сразу после принятия.
При получении данных сервер выводит количество принятых байтов. При получении сигнала `SIGHUP` выводит сообщение и продолжает работу.
Для ожидания сетевых событий и сигналов используется функция `pselect()`.

## Используемые технологии
* C (C11)
* POSIX sockets
* POSIX Signals (`sigaction`, `sigprocmask`)
* `pselect()`
* GCC
* MSYS2 MSYS

## Реализация
Для работы сервера используются следующие компоненты:
* `server_fd` — серверный сокет, который ожидает новые подключения.
* `client_fd` — сокет активного клиента.
* `fd_set` — набор файловых дескрипторов для проверки готовности.
* `was_sighup` — флаг получения сигнала `SIGHUP`.
* `stop_server` — флаг завершения работы сервера.
* `sigprocmask()` — блокировка сигналов и сохранение исходной маски.
* `pselect()` — ожидание готовности сокетов с временной маской сигналов.

### Создание сервера
1. Создаётся TCP-сокет с помощью `socket()`.
2. Включается параметр `SO_REUSEADDR`.
3. Сокет связывается с адресом и портом через `bind()`.
4. Вызывается `listen()` для ожидания подключений.

### Обработка сигналов
1. Для `SIGHUP` устанавливается обработчик через `sigaction()`.
2. Обработчик не выполняет обычную обработку, а только устанавливает флаг `was_sighup`.
3. Сигнал блокируется через `sigprocmask()`, при этом сохраняется исходная маска.
4. Во время ожидания `pselect()` временно использует маску, в которой `SIGHUP` разрешён.
5. После получения сигнала основной цикл обнаруживает установленный флаг и выводит сообщение.
6. Для завершения сервера также обрабатывается `SIGINT`, который обычно отправляется при нажатии `Ctrl+C`.

### Обработка подключений и данных
1. Перед каждым вызовом `pselect()` заново формируется набор `fd_set`.
2. В набор добавляется серверный сокет и, если он существует, сокет активного клиента.
3. `pselect()` ожидает сигнал или готовность одного из сокетов.
4. При готовности серверного сокета вызывается `accept()`.
   * Если активного клиента ещё нет, новое соединение сохраняется в `client_fd`.
   * Если клиент уже подключён, дополнительное соединение сразу закрывается.
5. При получении данных вызывается `recv()`, после чего сервер выводит количество принятых байтов.
6. Если клиент отключается, его сокет закрывается.
7. При завершении программы закрываются клиентский и серверный сокеты, а исходная маска сигналов восстанавливается.

## Сборка и запуск
Для сборки используется GCC из MSYS2 MSYS, поскольку программа использует POSIX-функции `pselect()`, `sigaction()` и `sigprocmask()`.

### 1. Установка компилятора
Открой терминал MSYS2 MSYS и выполни:
```bash
pacman -S --needed gcc
```

### 2. Переход в папку проекта
```bash
cd /c/mtcd/Monitor
```

### 3. Компиляция
```bash
gcc -std=c11 -Wall -Wextra server.c -o server.exe
```

### 4. Запуск
```bash
./server.exe
```
Сервер должен вывести сообщение о запуске и продолжить ожидать подключения.

## Проверка работы

### 1. Подключение клиента и отправка данных
Пока сервер работает в MSYS2 MSYS, открой PowerShell или используй PowerShell из терминала UCRT64. Выполни:
```powershell
$c1 = [System.Net.Sockets.TcpClient]::new("127.0.0.1", 5000)
$s1 = $c1.GetStream()
$b1 = [Text.Encoding]::UTF8.GetBytes("hello from UCRT")
$s1.Write($b1, 0, $b1.Length)
```
В окне сервера появятся сообщения о подключении и полученных данных. Для строки `hello from UCRT` размер данных составляет 15 байт.

### 2. Проверка дополнительного подключения
Не закрывая первое соединение, в PowerShell создай второго клиента:
```powershell
$c2 = [System.Net.Sockets.TcpClient]::new("127.0.0.1", 5000)
$c2.Close()
```
Сервер должен сообщить о новом подключении и закрытии дополнительного соединения. Первое подключение при этом остаётся активным.

Закрой первого клиента:
```powershell
$c1.Close()
```
Сервер должен вывести сообщение об отключении клиента.

### 3. Проверка сигнала SIGHUP
Открой второе окно MSYS2 MSYS и найди процесс сервера:
```bash
ps -ef | grep server
```
Найди PID процесса ./server и отправь сигнал:
```bash
kill -HUP PID
```
Вместо `PID` укажи номер процесса. В окне сервера должно появиться сообщение о получении `SIGHUP`. Сервер продолжит работу.
>**ВАЖНОЕ УТОЧНЕНИЕ**: при поиске через ps -ef | grep '[s]erver.exe' не ищется процесс сервера (возможно такая ошибка только у меня), поэтому рекомендую юзать только предоставленный вариант для надежности

### 4. Завершение работы
В окне, где запущен сервер, нажми `Ctrl+C`. Сервер завершит основной цикл, закроет открытые сокеты и восстановит исходную маску сигналов.

## Пример вывода
```text
Server started on port 5000
New connection
Client accepted
Received data: 15 bytes
New connection
Extra connection closed
Client disconnected
Received SIGHUP
Server stopped
```

## Результат
Реализован TCP-сервер, который обрабатывает сетевые подключения и сигнал `SIGHUP` с помощью `pselect()`. Сервер поддерживает одно активное клиентское соединение, закрывает дополнительные подключения, выводит размер полученных данных и продолжает работу после получения `SIGHUP`. Использование маски сигналов и `pselect()` обеспечивает безопасную обработку асинхронных событий без состояния гонки.
